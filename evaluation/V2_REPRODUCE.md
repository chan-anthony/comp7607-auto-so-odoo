# Local-first revision: reproduction index

No credentials are needed for scoring cached examples or opening the HTML replay. Use a local Python environment with NumPy for scoring, and Matplotlib for plotting. The strong model receives synthetic email text only during explicitly enabled hosted inference. Never package .env files or API keys.

- Initial prospective panel and protocol: V2_PROTOCOL.md, build_v2_cases.py (150 calibration, 180 test). New challenge: build_authority_challenge.py (150, five separate business families).
- The corpus directory contains manifest.json, per-stage JSONL, calibration-partition.json, frozen-policies.json, and (revised corpus only) authority-policy.json. The 75/75 split keeps scenario variants together. Fit only into a new empty output location; freezing intentionally refuses overwrite.
- Recompute frozen baseline, verbal, token, raw Kev, rules-only and hybrid scores: python evaluation/score_v2.py CORPUS test (or stress). The correct score is the complete ERP action: review, or draft with exact SKU/quantity lines, not JSON validity.
- Revised policy: python evaluation/score_authority.py CORPUS test; python evaluation/authority_curve.py CORPUS test. Substitute stress for the controlled panel. The confirmation comparator is python evaluation/confirm_comparator.py CORPUS test. Thresholds are empirical on calibration; 20/30% are calibration operating points, not online quotas.
- Extraction code: addons/sale_email_order/models/sale_email_order.py. Token scoring, authority and calibrated gate are adjacent. Deployed frozen JSON weights are pure Python at inference. Logprob and verbal uncertainty share one generation. No testing labels, scenario IDs or strong model outputs enter the routing features.
- Native demo: open Local_First_Odoo_Replay.html from the deliverables folder. The emails and displayed Odoo draft IDs/lines are saved local records. Full integration setup is in ENVIRONMENT.md. For timed rounds use run_native.ps1 with a fresh round name and an absolute output directory. The manifest's mail_to_committed_decision_ms includes MIME handling, inference, routing, Odoo writes and transaction commit. A verifier-only benchmark is distinct: bench_kev_devices.py sends matched candidate/three-question requests to localhost CPU:8008 and GPU:8009. Do not expose these project services externally.
